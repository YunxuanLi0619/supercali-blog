Benchmark是什么？
专业术语：一套标准化的测试，用来比较不同模型或在同一任务上的表现。

包括了：测试数据（数据从哪里来？）输入格式（模型看到什么？）输出格式（模型要回答什么？）评分规则（怎么样算对？）运行环境（是浏览器答题？还是调用工具，运行代码？访问文件？）汇总方式（最终分数是准确率，通过率，胜率，还是人类偏好？）

benchmark是一套完整的协议。

常见的benchmark

| 类型   | benchmark     | 主要测什么             |
| ---- | ------------- | ----------------- |
| 知识考试 | MMLU          | 多学科知识与选择题能力       |
| 代码生成 | HumanEval     | 根据说明写函数并通过测试      |
| 真实工程 | SWE-bench     | 修理真实的github issue |
| 高难推理 | GPQA          | 研究生级别科学回答         |
| 综合评测 | HELM          | 多场景，多指标表现         |
| 人类偏好 | chatbot Arena | 用户更喜欢哪个模型         |
| 系统性能 | MLperf        | 训练/推理速度与部署表现      |
|      |               |                   |
三：benchmark的组成：
	一、任务：
	想测什么能力？
	二、数据：
	数据是题目来源
	三、输入输出格式：
	四、评分规则：
	准确率，通过率，胜率，排名分，多指标评分（鲁棒性，公平性，偏见性，效率，毒性）。
	五、运行环境：
	环境越复杂，越接近真实系统，复现难度越高。这些条件影响分数
	六、汇总方式：
	多任务怎么合成一个分数？（很多争议：比如：简单平均？不同任务的子任务加权？简单困难问题的处理？）-》所以我们不能够只看benchmark的总分，最好要看子项。
四：benchmark为什么会越来越难？
		benchmark从会不会答题，走向能不能完成真实任务。
五、benchmark分数说明什么？
	一：模型在某类任务上的相对表现。
	二：能暴露模型短板：某一个方向强，另一个方向弱。
	三：能推动研究方向：不同的benchmark会推动不同方向的发展。
六、benchmark不能说明什么？
	不能说明在所有的场景都可靠。

	几个常见问题：
		1.数据污染：测试题目出现在训练集当中
		2.过拟合榜单：模型开发者围绕某一个benchmark去开发优化
		3.题目质量的问题：有歧义，答案错误，测试不完整。。。。
		4.评测设置不透明。一个模型使用了工具，多轮检索，而另一个没有，那么直接比较分数就不公平。
		5.单一分数掩盖差异。一个总分无法告诉你是否适合你的具体场景，不同需求对应不同的benchmark
